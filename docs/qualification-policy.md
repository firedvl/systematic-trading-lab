# Qualification policy

Qualification is a set of visible gates, not a single score. It will cover out-of-sample and walk-forward stability, periods and instruments, drawdown, turnover, exposure, campaign-wide validation trade count, parameter and cost sensitivity, delayed execution, missing data, regimes, profit concentration, benchmarks, and search volume.

`qualification-gates-v1` is the approved policy. The strict loader rejects malformed proposals and mismatches between proposal status and gate approval flags. Missing or invalid metrics fail their gates, and disqualifying failures reject the experiment. Failed experiments cannot qualify. Holdout metrics remain hidden until a completed holdout receives an explicit logged qualification event. Any threshold change requires its own human-reviewed change and evidence; it cannot accompany strategy or parameter changes.

The approved benchmark, risk, exposure, concentration, sensitivity, regime-coverage, activity, and search-volume thresholds are recorded in `config/research/qualification-proposal.json`. They are project policy choices, not universal financial claims. Approval alone does not qualify a candidate or authorize holdout access.

Cost and delayed-fill sensitivity results remain separate candidates and cannot alter qualification thresholds. Candidate comparisons show each metric, failure, and missing result directly; they do not rank candidates with a composite score.

A qualification evidence manifest names each candidate's base validation folds, matched fixed-weight folds, doubled-cost variants, delayed-fill variants, and parameter neighbors. The evaluator loads only completed validation records from the named campaign that carry controlled-run provenance and exactly one report location and SHA-256 fingerprint. Manual and legacy completions cannot enter qualification. It verifies campaign, strategy, period, parent, dataset, universe, parameter, cost, and execution relationships before aggregation. It sums fills across the predeclared base-validation folds for the campaign-wide trade-count gate; return, Sharpe, drawdown, regime, and concentration gates continue to apply within each fold. It then writes a content-addressed report containing all source experiment IDs, aggregate metrics, gate results, and fingerprints. Missing, mislabeled, cross-campaign, or inconsistent evidence stops evaluation.

A holdout-run authorization can be stored only after the system rebuilds evidence from the registry and obtains `qualified` from an approved proposal with every gate approved and passing. The authorization binds one candidate ID, strategy version and family, parameters, cost and execution models, dataset and universe provenance, and the end of validation. A holdout must match those fields, name the qualified candidate as its parent, and begin after validation. Creating it consumes the authorization in the same transaction. Only then may the controlled runner read the exact holdout range. A load or simulation failure remains failed evidence and does not restore the authorization. The runner does not return holdout metrics or write a readable report. The candidate, manifest, proposal, and source experiment set can authorize at most one holdout even if campaign bookkeeping later changes the evidence fingerprint. A completed holdout can receive only one logged read event.

Report schema v2 calculates qualification metrics from the last equity point in each completed session; the detailed per-symbol ledger remains unchanged. Annualized volatility and the Sharpe ratio use 252 sessions and a zero reference rate. Gross exposure is long market value divided by equity. Period concentration is the share of all positive session profit supplied by the five largest positive sessions. Instrument concentration is the largest positive instrument profit divided by total positive instrument profit after fills and commissions. SPY close-to-close returns classify up and down sessions; strategy returns are compounded separately within each class.

Parameter-neighborhood runs are separate validation candidates linked to the base candidate. They consume campaign budget and may reveal fragility, but they cannot select a new parameter from validation results. Missing regime classes or undefined risk and concentration values fail any gate that requires them.
