# Architecture

The system is a sequence of explicit authorities:

```text
provider -> raw snapshot -> normalize/validate -> immutable dataset/catalog
        -> strategy target -> portfolio -> simulator
        -> qualification -> independent risk -> order manager -> paper broker
        -> broker events -> reconciliation -> append-only evidence
```

The data and simulation lines now exist for deterministic daily-bar research. A versioned point-in-time universe checks full-range membership before provider access. Strategies share semantics across backtest, replay, shadow, and paper, but produce targets or intents rather than orders. A separate SQLite registry owns campaign budgets, experiment lifecycle, recovery, split classification, qualification evidence, and one-time holdout authorizations. The experiment runner records and claims each candidate before simulation, then reads only its declared Parquet timestamp range and stores its metrics and report fingerprint or its failure. Walk-forward folds and cost, fill-delay, or parameter-neighborhood variants are separate linked candidates. Report schema v2 derives qualification metrics from complete session endpoints while retaining the per-symbol equity ledger. A committed evidence manifest assigns completed validation records to qualification roles; the aggregator verifies their relationships and writes an immutable, fingerprinted gate report without loading bars. An approved passing report can authorize one matching post-validation holdout record; creation and authorization consumption share one SQLite transaction. The controlled runner consumes that authority before it reads Parquet, requests only the bound timestamp range, validates complete XNYS sessions and universe coverage within that range, and stores metrics only in the protected registry field. Qualification remains separate from strategy code. Risk and order management independently reject unsafe intents. UTC is internal time; money and prices use `Decimal`; dataset evidence is content addressed and catalog metadata is reconstructible from manifests.

Runtime data lives under `TRADING_LAB_HOME`: `datasets/<version-id>/manifest.json`, `datasets/<version-id>/raw.jsonl`, `datasets/<version-id>/bars.parquet`, `reports/`, `quarantine/`, `catalog.sqlite3`, and `experiments.sqlite3`. The version ID binds stable provenance, including the universe fingerprint, plus raw and normalized fingerprints; corrected versions link through `parent_dataset_id` only when their universe provenance also matches. Dataset artifact files are authoritative and the catalog is a reconstructible index. Cataloged experiment runs verify catalog and stored manifest agreement, dataset and universe identity, range bounds, symbols, and complete XNYS sessions before simulation. They do not load bars outside the experiment period. Experiment records copy universe provenance from that manifest. The experiment registry is authoritative lifecycle evidence. The Alpaca integration is a read-only, provider-adjusted HTTP source; no broker module exists in the current phase.
