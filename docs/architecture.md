# Architecture

The repository has two research tracks that share domain types, strategy targets, the simulator, cost models, fingerprints, and Parquet encoding:

```text
                         ┌─> Rapid Research store/report ─> zero-authority export
data -> validated bars ──┤
                         └─> controlled experiment -> qualification -> paper controls
```

Rapid Research is the short daily exploration path. `rapid_strategies.py` is the post-V2 home for new strategy implementations; `strategy_registry.py` owns their public names and integer parameters. `rapid_data.py` resolves cataloged daily data or validates a local CSV/Parquet import. `rapid_research.py` runs backtests, sweeps, chronological walk-forward folds, stress reruns, metrics, and comparisons. `rapid_store.py` owns only `rapid-research.sqlite3` and `rapid-research/{datasets,reports,candidates}`. These modules do not import controlled experiment, qualification, holdout, risk, order, paper, execution, reconciliation, broker, or V3 authority modules.

Candidate export is one-way. It can carry a selected result and its search ledger into human review, but every authority stays false. A later controlled plan must establish its own evidence and untouched evaluation boundary.

The system is a sequence of explicit authorities:

```text
provider -> raw snapshot -> normalize/validate -> immutable dataset/catalog
        -> strategy target -> portfolio -> simulator
        -> qualification -> independent risk -> order manager -> paper broker
        -> broker events -> reconciliation -> append-only evidence
```

The data and simulation lines support deterministic daily research plus research-only `1m` and `5m` regular-session replay, exact-range experiments, reports, and qualification evidence. Intraday paths use separate contracts and cannot authorize holdout access, paper execution, broker writes, or live trading. A versioned point-in-time universe checks full-range membership before provider access. Per-symbol strategies receive one completed bar at a time. Portfolio strategies use a separate backtest-only boundary that receives all bars for one complete timestamp slice plus immutable per-symbol history through that close. The V1/V2 boundary accepts or rejects one full-universe long-only target set, caps total target weight at one, and schedules accepted targets no earlier than the next configured symbol bar. Due reductions execute before buys so a rotation can use sale proceeds without depending on symbol order. The V3 boundary instead records every complete-slice desired-state evaluation, queues only changed binary states under a versioned FIFO delay, sizes entries once, and closes held quantities on exits. It has no periodic rebalance. Its paired zero-cost replay uses the same semantic trace and remains diagnostic-only. Strategies produce targets or intents rather than orders. V1/V2 keep their frozen registry and runner semantics. V3 uses disjoint `intraday_v3_*` tables for its verified publication seal, plan, 60 reservations, four dataset bindings, stored specs, source review, per-candidate source bindings, lifecycle, publication journal, integrity conflicts, and result evidence. The static plan creates no rows. Materialization itself verifies the exact GitHub/main-attested preregistration seal and its pre-first-bar transparency-log timestamp, then stores the exact seal bytes with the plan. Dataset binding resolves four IDs through the shared catalog and validates all complete raw and normalized artifacts before one transaction writes any binding or stored spec. Source review reruns the artifact assessment and requires the reviewed fingerprint. The V3 runner accepts no strategy, date, cost, delay, cash, dataset, review ID, or authority override. It claims one stored spec and a private lease token, validates the complete dataset before a range-limited Parquet read, heartbeats, and reverifies the reviewed source. The registry commits an immutable canonical-report intent first, create-only publishes and directory-syncs the exact final bytes, and only then commits completion. Stale recovery transfers the intent owner atomically and finalizes that same evidence; completed-intent reconciliation restores a missing file, so a crash cannot leave a permanent unregistered report. Substituted completed bytes create immutable conflict evidence and block qualification without rewriting the completed result. `intraday-backtest-report-v2` is not accepted by the V1 evaluator. Its V3 binding uses only realistic-cost metrics, derives the five report roles from the immutable registry plan, fingerprints every one of the 60 terminal source records, and cannot create authority. Daily holdout and paper controls remain separate. UTC is internal time; money and prices use `Decimal`; dataset evidence is content addressed and catalog metadata is reconstructible from manifests.

Program 009 is a separate pre-dataset source-qualification boundary. Its future active packet can set
only `provider_contact`, `credential_access`, `source_requests`, and `source_qualification`. The fixed
path is raw Alpaca SIP five-minute pages -> create-only private retention -> raw structural validation
-> authoritative XNYS RTH projection -> exact canonical completeness. The output is source-engineering
evidence, not a catalog dataset or strategy input. Activation, one-use claim, full acquisition,
dataset admission, strategy execution, controlled/protected access, PAPER, broker writes, and live
execution remain distinct authorities.

Runtime data lives under `TRADING_LAB_HOME`: `datasets/<version-id>/manifest.json`, `datasets/<version-id>/raw.jsonl`, `datasets/<version-id>/bars.parquet`, `rapid-research.sqlite3`, `rapid-research/`, `reports/`, `quarantine/`, `catalog.sqlite3`, `experiments.sqlite3`, and `execution.sqlite3`. Rapid, controlled experiment, and execution databases have disjoint table namespaces and authority. The version ID binds stable provenance, including the universe fingerprint, plus raw and normalized fingerprints; corrected versions link through `parent_dataset_id` only when their universe provenance also matches. Dataset artifact files are authoritative and the catalog is a reconstructible index. Cataloged experiment runs verify catalog and stored manifest agreement, dataset and universe identity, range bounds, symbols, and complete XNYS sessions before simulation. They do not load bars outside the experiment period. Experiment records copy universe provenance from that manifest. The experiment registry is authoritative lifecycle evidence. The execution database owns broker-free intents and append-only hash-chain evidence; later slices add immutable paper authorizations, pending risk-capacity reservations, single-submitter claims, and broker state without allowing broker snapshots to replace local expected state. The Alpaca integrations are a read-only provider-adjusted market-data source and a separate fixed-origin GET-only paper account-state reader. The paper reader has no broker mutation method. Its versioned exact-origin snapshot attestations share the execution journal and are required for baseline and later reconciliation use.
