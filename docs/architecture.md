# Architecture

The system is a sequence of explicit authorities:

```text
provider -> raw snapshot -> normalize/validate -> immutable dataset/catalog
        -> strategy target -> portfolio -> simulator
        -> qualification -> independent risk -> order manager -> paper broker
        -> broker events -> reconciliation -> append-only evidence
```

The data and simulation lines support deterministic daily research plus research-only `1m` and `5m` regular-session replay, exact-range experiments, reports, and qualification evidence. Intraday paths use separate contracts and cannot authorize holdout access, paper execution, broker writes, or live trading. A versioned point-in-time universe checks full-range membership before provider access. Per-symbol strategies receive one completed bar at a time. Portfolio strategies use a separate backtest-only boundary that receives all bars for one complete timestamp slice plus immutable per-symbol history through that close. The V1/V2 boundary accepts or rejects one full-universe long-only target set, caps total target weight at one, and schedules accepted targets no earlier than the next configured symbol bar. Due reductions execute before buys so a rotation can use sale proceeds without depending on symbol order. The development-only V3 boundary instead records every complete-slice desired-state evaluation, queues only changed binary states under a versioned FIFO delay, sizes entries once, and closes held quantities on exits. It has no periodic rebalance. Its paired zero-cost replay uses the same semantic trace and remains diagnostic-only. Strategies produce targets or intents rather than orders. A separate SQLite registry owns campaign budgets, experiment lifecycle, recovery, split classification, qualification evidence, and one-time holdout authorizations. The experiment runner records and claims each candidate before simulation, then reads only its declared Parquet timestamp range and stores its metrics and report fingerprint or its failure. Walk-forward folds and cost, fill-delay, or parameter-neighborhood variants are separate linked candidates. Report schema v2 derives daily qualification metrics from complete daily session endpoints while retaining the per-symbol equity ledger; `intraday-backtest-report-v1` uses completed New York session endpoints and retains flat-session evidence. `intraday-backtest-report-v2` is not accepted by the V1 intraday qualification evaluator and has no campaign execution path. A committed evidence manifest assigns completed daily validation records to qualification roles; the aggregator verifies their relationships and writes an immutable, fingerprinted gate report without loading bars. An approved passing daily report can authorize one matching post-validation holdout record; intraday qualification evidence cannot. The controlled daily runner consumes holdout authority before it reads Parquet, requests only the bound timestamp range, validates complete XNYS sessions and universe coverage within that range, and stores metrics only in the protected registry field. Qualification remains separate from strategy code. Risk and order management independently reject unsafe intents. UTC is internal time; money and prices use `Decimal`; dataset evidence is content addressed and catalog metadata is reconstructible from manifests.

Runtime data lives under `TRADING_LAB_HOME`: `datasets/<version-id>/manifest.json`, `datasets/<version-id>/raw.jsonl`, `datasets/<version-id>/bars.parquet`, `reports/`, `quarantine/`, `catalog.sqlite3`, `experiments.sqlite3`, and `execution.sqlite3`. The version ID binds stable provenance, including the universe fingerprint, plus raw and normalized fingerprints; corrected versions link through `parent_dataset_id` only when their universe provenance also matches. Dataset artifact files are authoritative and the catalog is a reconstructible index. Cataloged experiment runs verify catalog and stored manifest agreement, dataset and universe identity, range bounds, symbols, and complete XNYS sessions before simulation. They do not load bars outside the experiment period. Experiment records copy universe provenance from that manifest. The experiment registry is authoritative lifecycle evidence. The execution database owns broker-free intents and append-only hash-chain evidence; later slices add immutable paper authorizations, pending risk-capacity reservations, single-submitter claims, and broker state without allowing broker snapshots to replace local expected state. The Alpaca integrations are a read-only provider-adjusted market-data source and a separate fixed-origin GET-only paper account-state reader. The paper reader has no broker mutation method. Its versioned exact-origin snapshot attestations share the execution journal and are required for baseline and later reconciliation use.
